# 2채널 단계별 구현·검증 기록

2026-09-23. 기존 영상 A=위, floor.mp4 B=아래. Windows PC 한 대를 전제로 구현했다. 개발·실행 검증 호스트는 macOS이며 Windows 물리 출력 검증과 구분한다.

## 1단계 — Electron 실행·출력·미디어 기반

구현: Electron 44.4.5, contextIsolation/sandbox, 제한된 preload IPC, 운영 창 및 출력 A/B, 명시적 디스플레이 매핑, 단일 모니터 미리보기, 허용 경로만 제공하는 로컬 HTTP 미디어 서버.

검증:
- HTTP 206 구간 읽기·suffix range·HEAD·416·디렉터리 이탈 차단 통과.
- 동일 디스플레이 중복 지정/없는 ID 차단, 음수 화면 좌표 보존 통과.
- 실제 Electron에서 운영 창과 두 출력 생성, A 311.266667초/B 348.765083초 메타데이터 확인.
- 초기 ESM app-ready 대기 교착을 발견하여 whenReady().then() 초기화 구조로 수정.

상태: 구현 및 macOS 실제 앱 검증 완료. Windows 디스플레이의 fullscreen/케이블 재연결 검증은 6단계.

## 2단계 — 전역 해파이 장면

구현: 1920×2160 공통 좌표, 위/아래 setViewOffset, 중앙 seed·절대 시간·공통 개체 탄생 시각, 아래→위 이동, 아래 B에서 카메라 통과, 공통 배경 gradient, 양쪽 일괄 SVG fallback.

검증:
- 실제 Three.js 투영 행렬로 동일 경계 점이 A 하단(-1)과 B 상단(+1)에 일치함을 확인.
- 16개 개체의 아래→위 통과, seed/time 동일 시 위치와 애니메이션 시간 동일성 통과.
- 실제 GLB를 양쪽에서 로드하고 최대 16개 장면의 위/아래 스크린샷 저장·확인.
- 미리보기 창 장식 때문에 content 비율이 달라지는 문제를 useContentSize로 보정.

상태: 구현 및 논리/렌더 검증 완료. 실물 경계의 scanout 차이, 베젤/프로젝터 보정은 미검증.

## 3단계 — 중앙 회차·두 영상 동기

구현: A 기준 중앙 컨트롤러, 두 미디어 prepare 후 예약 재생, IPC 왕복 시계 보정, B 시간 추종, 공통 fade/hold, 단일 오디오 소유권, 일시정지·재개·리허설 seek. 태블릿 문장·기존 자막·트리거영상은 A에 유지.

검증:
- 기존 회차 테스트 및 새 중앙 컨트롤러의 10회 반복·중복 제거·HOLD pending·설정 다음 회차 적용 테스트 통과.
- 실제 두 영상 재생 시각 비교, 공통 페이드, 정지 중 currentTime 유지, 재개 통과.
- 실제 ended → HOLD → 다음 회차에서 양쪽 이전 해파이 0개, 대기 입력 1회 이월 확인. 리허설에서는 대기만 2초로 줄여 실행하고 테스트 전용 설정을 사용했다.
- 트리거영상 pause 확장 중 발견한 ASI 오류를 수정하고 콘솔 오류 없이 재검증.
- 실제 비교 시각은 output/playwright/verification.json에 저장한다. 개별 측정은 하드웨어 동기 성능 보장이 아니다.

상태: 구현 및 실제 앱 기능 검증 완료.

## 4단계 — 태블릿·장애 복구

구현: Game Poem snapshot 및 원본 SHA-256 기록, A iframe 하나만 host, 중앙 수락 후 ack, renderer 재생성 시 중앙 session/회차 유지, 공통 정지 및 준비 후 운영자 재개, 최대 3회 창 자동 복구.

검증:
- 실제 Game Poem UI에서 문구 추가 1회 증가, 제거는 증가 없음, 재추가 1회 증가 확인.
- iframe → 중앙 → ack 경로와 재전송 동안 중복 집계 없음 확인.
- 실제 B renderer 강제 종료 → 양쪽 정지 → B 창 재생성/미디어 준비 → 재개 확인.
- 이전 테스트의 형제 저장소 직접 import를 bundled snapshot으로 변경하여 단독 저장소 테스트 가능.

상태: 동일 컴퓨터 실제 앱 통합 검증 완료. 물리 태블릿·현장 PeerJS 네트워크는 6단계에서 확인한다. 완전 오프라인 LAN 전송은 추가 요구로 남겨 두었다.

## 5단계 — 운영·Windows 패키지

구현: 한국어 운영 UI, 영상 교체, 디스플레이 지정, 회차/해파이/오버레이 설정, JSON import/export, 파일 기반 원자적 설정 저장, 로그, 화면 절전 방지, 로컬 미디어를 포함한 Windows x64 포터블 패키징.

검증:
- 설치 설정 저장/재로드, 잘못된 topology·room·수치·버전 거부 테스트 통과.
- 전체 단위 테스트 24개 통과.
- 웹 공유 모듈 변경 후 Workbox precache 60개 해시 갱신.
- Windows x64 배포 폴더 생성. 원본 MOV/Blender 작업본을 제외하고 실행에 필요한 영상·모델·오디오·태블릿 자산 포함.
- 패키지 런타임 파일 SHA-256 목록 생성. 실제 Windows EXE 실행/코드 서명은 수행하지 않음.
- 최종 패키지 resources/app를 macOS Electron에서 별도로 실행하여 저장소 밖 경로에서도 같은 통합 테스트가 통과했다. 그 결과 경로는 verification.json의 appRoot로 식별한다. 페이지 JavaScript 오류는 0개였다.

상태: 로컬 검증 및 Windows 패키지 생성. 운영 가이드는 dual-channel-operations.md.

## 6단계 — Windows 현장 수락 검사

아직 완료하지 않았다. 현재 환경은 macOS이고 목표 Windows PC·두 실물 디스플레이·태블릿에 연결되어 있지 않다.

필요한 검사:
- 실제 위/아래 디스플레이 매핑과 F/Esc, 화면 재연결/해상도/DPI 변경.
- 물리 태블릿의 문장 입력과 재접속, 인터넷 의존성 및 현장 네트워크.
- 경계 통과 고속 촬영, 출력 지연·밝기·색상·베젤 간격, 필요시 단일 span 창 방식과 비교.
- 최종 해상도에서 최대 16개 해파이+3개 트리거영상 성능.
- 8시간 또는 하루 운영 시간 이상의 연속 상영, 오디오 연속성과 메모리.

두 개의 BrowserWindow는 하드웨어 genlock/frame lock을 보장하지 않는다. 위 단계가 완료되기 전에는 전시장 운영 검증 완료로 표현하지 않는다.

## 2026-09-24 — EXE 더블클릭 자동 상영

- 설치 모드에서 운영 창을 기본 숨김으로 생성하고, 두 출력의 준비 완료와 전체화면 상태를 확인한 뒤 자동으로 1회 시작한다.
- 유효한 저장 배치를 우선 복원한다. 미지정/연결 ID 변경 시 정확히 두 화면이면 y→x 좌표 순서로 A/B를 지정하고 저장한다.
- 화면 부족·세 대 이상 미지정·미디어 오류·45초 준비 시간 초과는 운영 창으로 안내한다. 유효한 저장 배치가 있으면 세 대 이상에서도 지정된 두 출력만 사용한다.
- `--preview` 수동 실행은 유지한다. 설치 후 로그인 자동 실행은 변경하지 않았다.
- 단위 테스트 31개 통과. 신규 배치/기존 역순 배치 복원/화면 부족을 실제 Electron에서 검증했다. 영상은 실제 파일을 사용하고 모니터/네이티브 전체화면은 macOS 테스트 어댑터로 모의 처리했다.
- 결과: `output/playwright/startup-verification.json`. Windows 물리 출력의 최종 확인은 현장 장비에서 필요하다.
