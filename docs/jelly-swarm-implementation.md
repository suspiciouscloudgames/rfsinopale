- 기존 트리거 집계, 중복 방지, 보류 이벤트, 최소/최대/트리거당 수 보존.
- 웹·데스크톱 설정 UI에 모드, 근경 개수, 밀도, 군집 대기/증가 시간, 불투명도 추가. 다음 회차에 적용.

## 2. 근경·등장 순서 — 완료

- 기존 웹 cameraPassPosition, 데스크톱 jellyPose 경로 함수 변경 없음.
- 기존 모델의 투영 크기와 전역 카메라 위치로 준비 시점을 결정한다. 실제 삼각형의 외곽/가림 여부를 매 프레임 측정하는 방식은 아니다.
- 크기 기준 화면 높이 85% 이하, 화면 중심 영역에 위치, 카메라 앞 조건 후 1초 안정 시간. 웹 52.5초/데스크톱 40.5초의 준비 시점 이후 기본 3초 대기, 24초 군집 증가.
- 각 군집 개체의 지연으로 먼 군집→중경 순서가 부드럽게 겹친다.
- 웹 E키 테스트에서 0회 트리거·근경 4개, 초기 군집 0개 확인.

## 3. 군집 렌더링 — 완료

- 절차적 윤곽·내부 고리·박동 셰이더를 사용하는 인스턴스 평면. 별도 대용량 파일이나 개체별 AnimationMixer 없음.
- 300/840/1500개 프리셋. 크기·깊이·회전·박동 위상과 5개 군집 중심의 밀도 차이 적용.
- 실제 화면 점검 후 첫 버전보다 개체 크기와 윤곽 대비를 올려 더 밀집된 반투명 군집으로 조정.
- GPU 자원은 동일 회차에서 재사용, seed/밀도/종횡비 변경 시 이전 geometry/material 해제.
- 원경 인스턴스는 깊이 순서로 배치, depthWrite=false 및 근경보다 앞선 투명 렌더 순서. 교차하는 반투명 면의 완전한 물리적 정합성은 목표로 하지 않음.

## 4. 통합 검증 — 완료

- 웹: 군집 840개 + 근경 4개, 오류 로그 없음. 그리기 호출 8→9회, 초기 미리보기에서 약 120 FPS 관측.
- 웹: 실제 다음 회차에서 근경/군집 표시 수가 즉시 0으로 돌아가는 것 확인.
- Electron: 임시 userData로 검증해 사용자의 저장 설정을 건드리지 않음. A/B 두 창에서 최종 군집의 실제 표시 확인. 같은 seed/시간/전역 좌표를 사용.
- Electron: 리허설 이동을 사용해 3개 회차 및 다음 회차 적용 확인. 기존 모드로 저장한 뒤 회차 3에서 트리거 0회→해파이 1개, 트리거 2회→2개 확인. 페이드 구간에서 군집이 꺼지고 기존 모델만 표시됨을 화면으로 확인.
- 로컬 미리보기에서 양쪽 출력 약 105~120 FPS 범위 관측(영상 이동/창 조작 포함). 실제 프로젝터 해상도의 장시간 부하·메모리 측정은 수행하지 않았으며 이 수치를 설치 장비 성능 보장으로 해석하지 않음.
- 최종 자동 테스트 28개 통과. 구성 복구, 설정 유효성, 군집 등장 순서, 결정적 배치와 밀도, 기존 회차/이벤트/두 채널 테스트 포함.
- WebGL 또는 모델 실패 시 기존 대체 실루엣으로 진행하며 GPU 군집은 생략.

## 확인 방법

웹 상영을 새로고침하고 시작 후 E키를 누른다. 카메라 통과 연출 후 군집이 서서히 나타난다. T키 입력 횟수는 군집 구성에 영향을 주지 않는다.
복구: 운영 설정 → 해파이 구성 → 기존 횟수 연동으로 복구 → 저장. 다음 회차부터 적용된다.

## 등장 밀도 후속 조정

무작위 지연이 짧은 구간에 집중되던 방식을 개체별로 고르게 분산된 등장 순서로 교체했다. 전체 증가 시간의 80% 동안 새 개체가 합류하고, 개체별 20% 길이의 부드러운 페이드인이 겹친다. 두 출력의 순서는 동일하며 깊이 정렬은 보존한다. 실제 등장 개체 수를 반환하도록 운영 지표도 수정했다. 3개 밀도에서 초기/중간 개체 수, 등장 간격, 불투명도의 연속성과 종료를 검증했으며 자동 테스트 29개가 통과했다.

- 군집 증가 기본 시간을 24초로 늘렸다. 초반 개체 수가 적도록 등장 누적 수에 이차 곡선을 적용하며, 새 개체는 첫 19.2초에 걸쳐 합류하고 각각 4.8초 동안 부드럽게 나타난다. 기존 기본값 12초는 한 번 24초로 전환되며 이후 사용자 설정은 유지된다.
