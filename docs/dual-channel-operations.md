# Windows 2채널 상영 운영

구현일: 2026-09-23. 위 A=기존 영상, 아래 B=assets/floorVideos/floor.mp4.

## Windows에서 실행

1. `dist/Drifting Sea-win32-x64` 폴더 전체를 Windows PC로 복사한다. EXE만 옮기면 안 된다.
2. Windows 디스플레이 설정을 **확장**으로 두고 두 디스플레이의 해상도·주사율을 확인한다. 가능하면 동일 주사율을 사용한다.
3. `Drifting Sea.exe`를 더블클릭한다. 별도 Node.js/Python 설치는 필요 없다.
4. 저장된 A/B 배치를 복원하고, 양쪽 영상이 준비되면 **자동으로 두 화면 전체화면 상영을 시작**한다. 운영 창은 숨겨진다.
5. 최초 실행 또는 저장한 화면 ID가 바뀐 경우, 연결된 디스플레이가 정확히 두 대이면 Windows 좌표의 위쪽을 A, 아래쪽을 B로 자동 지정하고 저장한다. Windows 설정이 좌우 배치라면 왼쪽=A, 오른쪽=B로 선택한다. 물리 위치와 다르면 O 키로 운영 창을 열고 일시정지 → 배치 수정 → 시작한다. 화면 부족, 세 대 이상이고 유효한 저장 배치가 없음, 미디어 준비 실패일 때만 운영 화면에 안내한다.
6. 종료는 운영 창의 **앱 종료** 버튼을 사용한다. 출력 창을 닫으면 공통 일시정지한다. 운영 창 닫기는 일시정지 후 최소화하며 작업표시줄에서 복귀할 수 있다.

현재 제공물은 서명되지 않은 Windows x64 포터블 폴더다. Windows 실제 실행, 출력 포트·프로젝터 조합, SmartScreen 및 장시간 상영은 현장에서 검증해야 한다. ARM64 네이티브 빌드는 포함하지 않았다.

## 재생 정책

- A: 1440×1080, 30fps, 311.266667초. 기존 영상.
- B: 1920×1080, 24000/1001fps, 348.765083초. 제공된 floor.mp4, 오디오 트랙 없음.
- A 기준 종료 60초 전 양쪽 영상·A 자막/문장/트리거영상이 함께 페이드한다.
- 해파이는 전체 논리 화면 1920×2160에서 아래 B→위 A로 이동한다. 공통 개체 수는 기본 1~16개이며 창당 별도 집계하지 않는다.
- 끝난 뒤 해파이를 30초 유지한다. 다음 회차 준비는 두 출력에 대해 수행하며 새 회차에 이전 해파이를 제거한다.
- B가 긴 현재 구성에서는 B의 마지막 약 37.50초를 독립적으로 이어 재생하지 않는다. A의 종료에 맞춰 페이드하고 다음 회차에 처음부터 재생한다. B를 짧은 영상으로 교체하면 A 회차 안에서 반복한다.
- 기존 사운드트랙은 A에서만 재생하며 정상 해파이 유지 구간에도 계속된다. 운영자 정지·장애에서는 함께 멈춘다.
- 영상 맞춤 기본값은 contain이다. 기존 A가 4:3이므로 16:9 출력에는 좌우 여백이 생긴다. cover를 선택하면 화면을 채우지만 일부가 잘린다. 해파이는 여백과 무관하게 전체 설치 영역을 사용한다.

## 운영 설정과 단축키

운영 창: 페이드·유지 시간, 해파이 최소/최대/트리거당 수, 트리거영상 불투명도·길이·동시 수, A/B contain/cover, 영상 파일 교체, 설정 JSON 내보내기·가져오기.

- 시간·개체 수는 다음 회차부터, 트리거영상은 다음 입력부터 반영한다.
- 영상 교체·화면 변경은 먼저 일시정지한다. 영상 교체 후 새 회차로 시작한다.
- 가져온 JSON은 앱 종료 후 다시 실행한다. 다른 PC에서 내보낸 외부 영상 절대 경로와 display ID는 해당 PC에서 다시 지정해야 할 수 있다.
- 기본 미디어는 앱 내부 경로를 사용한다. 운영 창에서 선택한 외부 영상은 해당 경로에 계속 있어야 한다.
- `Enter`: 시작/재개, `Space`: 공통 일시정지, `F`: 양쪽 전체화면, `Esc`: 양쪽 창 모드, `O`: 운영 창, `T`: 테스트 문장트리거, `E`: 페이드 시작으로 이동.
- 리허설 패널에서 종료 2초 전, 임의 재생 시각 이동, 출력 재로딩이 가능하다. 실제 회차·집계에 영향을 준다.
- 설정과 로그: Windows 기본 `%APPDATA%\drifting-sea-screening\installation.json`, `installation.log`. 로그는 시작/정지/복구 이벤트를 기록한다.
- `layout.width`, `layout.height`, `layout.gap`은 논리 화면 단위다. 기본값 1920/1080/0. 베젤 간격 보정은 JSON에서 gap을 조정하고 앱을 재시작한다. 각 창의 Windows DIP 좌표와 별개다.
- room 및 논리 크기를 변경할 때는 JSON 가져오기 후 재시작한다. 평면 상하·같은 물리 폭을 기본으로 하며 서로 다른 물리 폭, 프로젝터 왜곡·중첩 블렌딩은 별도 보정이 필요하다.

## 태블릿

기존 Game Poem PeerJS 연결을 유지한다. 기본 room은 `sinopale`이다. 실제 태블릿은 기존 배포 Game Poem에 같은 room으로 접속한다. 상영 room당 host는 이 앱의 A iframe 하나다. 동일 room의 다른 상영 페이지를 동시에 열지 않는다.

A iframe이 받은 이벤트는 중앙 컨트롤러가 검증·중복 제거하고 나서 ack한다. B는 독립 host나 별도 카운터가 아니다. 출력 renderer 재시작 중에도 중앙 세션/집계를 유지한다. 앱 전체를 다시 시작하면 신규 세션이며 기존 정책대로 이전 세션의 이벤트는 새 회차로 넘기지 않는다.

`desktop/tablet`은 형제 gamepoem의 파일을 해시 기록과 함께 포함한 snapshot이다. 따라서 설치 PC에 형제 저장소가 없어도 표시/통신 코드는 실행된다. Game Poem 원본 변경 후 `npm run tablet:sync`로 snapshot을 갱신하고 연동 테스트와 Windows 패키징을 다시 수행한다. 원본 저장소는 이번 작업에서 수정하지 않았다.

영상·모델·오디오는 로컬이지만 **태블릿 PeerJS 연결은 인터넷/시그널링 연결에 의존**한다. 완전 오프라인 LAN WebSocket 모드는 구현하지 않았다. 로컬 HTTP 서버는 127.0.0.1에만 바인딩하며 물리 태블릿이 그 주소로 접속하는 구조가 아니다.

## 장애 처리

- 재생 진행이 2.5초 이상 멈추면 공통 일시정지한다. 파일/장치를 확인하고 시작/재개로 재동기화한다.
- 출력 renderer가 종료되면 공통 정지 후 해당 창을 최대 3회 재생성한다. 준비됨 확인 후 운영자가 재개한다.
- 화면 추가/제거/해상도 변경 시 설치 모드는 공통 정지한다. 모니터 매핑을 확인하고 적용한 뒤 재개한다.
- WebGL/모델 실패는 양쪽 모두 같은 실루엣 대체 모드를 사용한다. 원래 GLB로 복귀하려면 원인을 해소하고 앱을 재시작한다.
- 새 출력이 준비되기 전 재생을 시작하지 않는다. 설정 창 포커스 이동은 출력 재생을 정지하지 않는다.
- 운영자가 설정하지 않은 자동 로그인 실행·Windows 업데이트·화면 보호기 정책은 변경하지 않는다. 프로세스 전체 종료 이후 자동 재실행도 OS 운영 설정 영역이다.

## 개발·검증·패키징

```sh
npm ci
npm run desktop:preview
npm test
npm run desktop:verify
npm run desktop:package:win
```

- `desktop:preview`: 한 모니터에 상하 두 창을 만들어 기능을 확인한다. 물리 디스플레이 프레임 동기 검증을 대체하지 않는다.
- `desktop`: 설치 모드. 최초에는 운영 창에서 두 디스플레이를 지정한다.
- `desktop:verify`: 별도 임시 설정 디렉터리·테스트 room으로 실제 Electron을 구동한다. 실제 두 영상/모델, 중앙 회차, 태블릿 UI, renderer 장애를 검사한다. 평소 운영 설정을 덮어쓰지 않는다. 결과는 output/playwright/verification.json 및 스크린샷에 저장한다.
- `desktop:package:win`: 필요한 런타임 자산만 포함한다. Blender 원본·원본 MOV·preview_frames·메인 3D 체험 번들은 패키지에 넣지 않는다. 기본 미디어는 resources/app 내부에 일반 파일로 배치되어 교체 가능하다.
- 기존 웹 상영은 README의 Python 서버 방식으로 계속 실행할 수 있다. Electron에서는 서비스 워커를 등록하지 않는다. 공유 video/ 파일 변경 후 웹 배포를 위해 `npm run cache`를 실행한다.

## 현장 수락 검사 — 아직 미완료

동일 Windows PC에서 위/아래 실물 매핑, F/Esc, 포커스 전환, 음원 한 번만 출력, 케이블 분리/재연결, 실물 태블릿 입력, 프로젝터 밝기, 경계 통과를 확인한다. 특히 서로 다른 영상 프레임률과 디스플레이 주사 위상이 있으므로 이 구현은 하드웨어 frame lock 보장이 아니다.

최종 장비에서 16개 해파이·트리거영상 동시 3개 상태로 프레임 시간과 누락 프레임을 측정하고, 최소 8시간 또는 실제 하루 운영 시간 중 더 긴 시간 동안 반복한다. 이 확인 전에는 장시간 전시 운영 검증 완료로 간주하지 않는다.

## 자동 시작 변경 (2026-09-24)

설치 모드는 기본 자동 시작이다. `--preview`는 수동 미리보기를 유지하며 `--preview --autostart`로 자동 시작 흐름을 미리 볼 수 있다. 최초 로딩 중에도 영상/모델 준비와 두 출력의 전체화면 상태를 기다리며, 중복 ready 알림으로 회차가 두 번 시작되지 않는다. 준비 실패 또는 45초 시간 초과 시 운영 창을 표시한다. 이 변경은 EXE 실행 시의 자동 상영이며 Windows 로그인 자동 실행 설정을 변경하지 않는다.

`npm run desktop:verify:startup`: 신규 설정·기존 배치 복원·디스플레이 부족 시나리오를 검사한다. macOS 검증에서는 디스플레이/네이티브 전체화면만 모의 처리하며 실제 영상 재생과 초기화 코드는 그대로 실행한다.

## 트리거영상 성능 설정

트리거영상 4종은 1920×1080 H.264로 제공한다. 영상 로딩 또는 표시 중 추가 문장트리거는 집계하지만 새 영상을 겹쳐 재생하거나 현재 영상을 재시작하지 않는다. 추가 영상 재생을 예약하지 않으며, 표시 종료 후 들어오는 새 문장트리거부터 다음 영상을 재생한다. 기존 표시 시간(기본 17초)과 짧은 소스의 반복 재생은 유지한다. 이전에 저장한 동시 표시 수는 1개로 적용한다.

연속 입력 검증: `node scripts/verify-single-overlay.mjs`.

## 해파이 실행 모드

항상 군집 구성·횟수 무관 모드로 실행한다. 이전 Windows 설정 또는 가져온 JSON에 `jellyMode: "trigger-count"`가 있어도 로드·저장 시 `composition`으로 적용한다. 운영 화면에서는 모드를 전환할 수 없다. 기존 횟수 연동 계산 코드는 보존하며 문장트리거 집계도 유지한다.
