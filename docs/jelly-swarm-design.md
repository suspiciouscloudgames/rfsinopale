## 목표와 이미지 해석

참조: 사용자가 첨부한 Screenshot 2026-09-23 at 11.11.01.png.
핵심은 해파이 하나하나의 정교함보다, 투명한 우산 형태가 수없이 겹쳐 물의 표면과 공간을 채우는 밀도다. 밝은 가느다란 테두리, 내부의 희미한 고리, 불균일한 크기와 빈 공간을 반영한다. 사진을 평면 배경으로 붙이지 않고 깊이가 있는 군집으로 해석한다. 사진 속 모델과 현재 GLB의 형태 차이는 근경/원경의 추상화로 연결한다.

## 보존 및 복구

- `ScreeningCycle.accept()`의 집계·중복 방지·다음 회차 이월과 `jellyCount()`의 기존 공식은 유지한다.
- 제안 설정 `jellyMode: "composition" | "trigger-count"`로 렌더링 구성만 선택한다.
- composition: 트리거 횟수와 무관한 고정 근경 구성 및 군집 밀도. 기본 근경은 카메라 통과 1개 + 기존 깊이 배치 3개, 총 4개로 시작한다.
- trigger-count: 지금의 minJellies/maxJellies/jelliesPerTrigger와 GLB 렌더링 경로를 그대로 사용하고 새 군집은 끈다. 카메라 통과 개체도 기존 방식 그대로 유지한다.
- 모드 변경은 다음 회차에 적용. 저장된 기존 개수 관련 값은 지우거나 덮어쓰지 않는다.
- 기존 테스트를 보존하고 두 모드를 각각 검증한다. `7fc99db`는 기존 구현 전체의 커밋 기준점이다.
- 트리거영상, 핫핑크 선, 태블릿 이벤트, T/E/F/Esc 기능과 영상 반복 주기는 이번 변경 대상이 아니다.

## 시퀀스

1. 기본 영상 재생 중에는 군집을 표시하지 않는다. 자산은 미리 준비한다.
2. 페이드아웃 시작: 현재 카메라 통과 해파이 및 깊이 배치 해파이를 기존처럼 등장시킨다. 웹에서는 `cameraPassPosition()`, 데스크톱에서는 `shared/show/scene.js`의 `jellyPose()`가 정의한 현재 경로·크기·방향을 각각 유지한다.
3. 카메라 통과 후 해당 개체의 외형이 식별되는 상태를 검출한다. 카메라 앞에 있고, 화면과 겹치며, 투영 크기가 화면 높이 약 85% 이하인 상태를 약 1초 유지하면 준비 완료로 본다. 이 수치는 실제 모델로 조정한다.
4. 준비 완료 후 3초 대기한다.
5. 12초 동안 먼 곳부터 군집을 드러낸다. 중경, 원경의 등장 시간을 2~4초 엇갈리게 하고 각 개체에도 작은 지연을 둔다. 특정 한 지점에서 모두 생성되거나 동시에 커지는 연출은 피한다.
6. 기본 영상이 사라진 뒤에도 군집은 부유하며 기존 30초 유지 시간을 따른다. 군집 연출이 영상 재시작 시간을 연장하지 않는다.
7. 다음 영상의 첫 프레임에 근경과 군집을 전부 즉시 숨기고, 등장 상태·시계를 초기화한다. 재사용 가능한 GPU 자원은 유지한다.

웹 기본 60초 페이드 + 30초 유지에서 카메라 통과는 현재 경로상 약 16초, 우측 상단 이동은 23초부터다. 외형이 충분히 드러나는 시점은 그보다 늦으므로 23초를 군집 시작으로 고정하지 않는다. 군집 타이밍은 실제 화면에서 확인한다.
페이드/유지 시간을 크게 줄여 전체 연출 시간이 부족하면 영상 반복 주기를 우선하고 군집은 남은 구간만 표시한다. 이 경우 모든 단계가 보장되지 않음을 운영 설정에 표시한다. 카메라 경로를 임의로 가속하지 않는다.
E키는 현재 회차의 페이드 시작 지점으로 이동시키는 기존 테스트 기능이다. 새 회차에서 E키를 사용해 처음부터 확인한다. 이미 진행 중인 연출을 E키로 재설정하는 기능은 별도 요청 없이는 추가하지 않는다.

## 표현 방식 비교

| 방식 | 장점 | 한계 | 선택 |
| --- | --- | --- | --- |
| 기존 GLB 수백 개 복제 | 근경과 형태 일치 | 개별 애니메이션, 정점 처리, 그리기 호출 부담 | 소수 근경만 사용 |
| 단순한 우산 모양 3D 메시를 인스턴싱 | 실제 입체감, 가벼운 변형 | 새 메시/셰이더와 형태 조정 필요 | 중경 대안 |
| 투명 실루엣을 입힌 작은 평면을 3D 공간에 인스턴싱 | 저비용으로 높은 밀도, 이미지와 유사한 겹침 | 가까이 오면 평면 티, 투명도 정렬 문제 | 군집 기본안 |
| 미리 렌더링한 군집 영상 | 실행 중 비용 예측 용이 | 깊이 변화 제한, 추가 대용량 자산 | 성능 부족 시 보조 대안 |

추천은 3D 근경 + 실루엣 군집의 혼합이다. 원경 개체를 각각 DOM/SVG/AnimationMixer로 만들지 않는다. 같은 렌더러/카메라의 깊이 공간에 배치한다.

## 군집 형태와 공간

- 중경 120~240개: 6~12종의 우산 윤곽/내부 고리를 작은 텍스처 묶음으로 공유한다. 기본 모델에서 얻은 실루엣과 추상적인 투명 고리 형태를 섞는다.
- 원경 500~1,500개: 더 작고 희미한 윤곽과 흔적으로 채운다. 이 수치는 초기 실험 범위이며 성능 보장 수치가 아니다.
- 현재 카메라 far=40 안에서 배치부터 시작하고, 근경 경로와 겹치지 않는 뒤쪽 영역을 확보한다.
- 화면 전체에 균등한 격자로 배치하지 않는다. 3~5개의 느슨한 군집과 어두운 빈 공간을 만들고 밀도가 다른 층을 겹친다.
- 가까운 곳은 크고 명료하고 비교적 빠르며, 먼 곳은 작고 저대비·저속이다. 주 흐름은 기존의 좌하단→우상단을 따르되 개체마다 작은 위상 차이를 준다.
- 이동·회전·수축 변형은 시간과 개체별 고정 난수로 계산한다. 프레임마다 난수를 다시 뽑지 않는다. 순간이동이나 깜빡임은 연출로 채택하지 않는다.
- 색은 회백색/옅은 청록 중심. 몸 전체를 발광시키기보다 얇은 테두리와 내부 고리만 강조해 화면이 하얗게 뭉개지지 않게 한다.
- 실제 굴절·물리 충돌·개체마다 그림자는 사용하지 않는다. 해파이 모양이 일부 흐트러지거나 겹치는 추상성은 허용한다.

## 렌더링 주의점

인스턴싱은 그리기 호출 수를 줄이지만 투명 픽셀의 반복 합성 비용까지 없애지는 않는다. 작은 평면의 빈 여백을 줄이고 화면을 덮는 총면적·중첩 수·해상도를 함께 관리한다.
군집은 깊이 층으로 묶고 뒤에서 앞으로 합성한다. 근경 불투명 모델과는 깊이 테스트를 유지하고, 반투명 군집은 깊이 기록을 끈다. 인스턴스 내부는 자동 정렬에 의존하지 않고 깊이 순서를 유지하거나 필요한 시점에 정렬한다. 완전한 투명 교차 정확도 대신 시각적으로 안정적인 결과를 목표로 한다.
현재 부모 컨테이너의 페이드 값에 더해 군집 자체의 등장 값을 곱한다. 기존 근경의 밝기 변화에는 새 군집의 등장 지연을 적용하지 않는다.
동일 AnimationMixer가 수백 개 늘지 않도록 군집의 박동·변형은 공유 셰이더에서 계산한다. 회차 전환 때 자원을 반복 생성·폐기하지 않되 모드 변경/종료 시 정리한다.

## 운영 설정 제안

- 구성 모드: composition / trigger-count
- 근경 GLB 수: 기본 4(카메라 통과 개체 포함)
- 군집 등장 대기: 기본 3초
- 군집 증가 시간: 기본 12초
- 군집 밀도: 낮음/보통/높음
- 군집 최대 불투명도, 크기 범위, 부유 속도

원경 수와 텍스처 해상도는 품질 프리셋으로 함께 조정한다. 사용자에게 렌더링 내부 옵션을 모두 노출하지 않는다.

## 구현 순서와 검증 기준

1. 구성 선택 분리: 기존 집계 함수는 보존. 0/1/100회 트리거에서 composition의 개체 구성이 같은지, trigger-count가 예전 공식과 같은지 테스트한다.
2. 근경 유지: 고정 4개 구성에서 기존 카메라 통과·깊이감·유영을 확인하고 등장 완료 신호를 조정한다.
3. 소규모 군집: 중경 실루엣 120개로 질감·겹침·등장 순서를 먼저 평가한다.
4. 원경 확대: 밀도와 겹침을 늘려 참조 이미지의 군집감을 맞춘다. 큰 화면에서 반복 무늬와 평면 경계를 점검한다.
5. 통합 검증: T/E키, 반복 시작 시 즉시 제거, 숨긴 탭 복귀, 화면 크기 변경, 모델 로드 실패, 모드 복구를 확인한다.
6. 성능 검증: 실제 상영 해상도에서 최소 3회차, 회차 후 메모리 안정성, 프레임 시간, 그리기 호출을 측정한다. 60fps를 목표로 하되 지속 30fps 미만이면 원경 밀도/해상도/중첩부터 줄인다. 기본 근경과 카메라 통과는 보존한다.

## 현재 추가된 데스크톱/2채널 구조와의 접점

작업 폴더에는 Electron의 상하 2채널 구현도 존재한다. 기존 변경 파일은 수정하지 않고 이 설계에 접점만 반영한다.
- 데스크톱의 `shared/show/controller.js::countJellies()`에도 기존 횟수 공식을 보존한다. countJellies와 syncBirths를 삭제하지 않고 composition 전용 고정 구성/등장 시간 선택을 추가하는 방식이다.
- 현재 데스크톱 `jellyPose()`는 하단 B에서 상단 A로 이동하는 별도 전역 경로다. 웹의 우상단 경로로 덮어쓰지 않는다.
- 군집의 seed, 개체 ID, 위치, 등장 시각은 shared/show에서 공유한다. 창마다 Math.random이나 프레임 누적 시계로 계산하지 않는다.
- 군집 등장 준비 판정도 전체 설치 화면 좌표와 중앙 시계로 한 번 결정해 A/B에 동일하게 전달한다. 개별 창의 잘린 화면 크기로 따로 판정하지 않는다.
- 같은 군집 장면을 A/B 카메라가 나눠 본다. 연결 경계에서 개체 위치, 박동, 불투명도, 등장 시각이 이어져야 한다.
- 품질 조정은 중앙에서 동일하게 적용하고 ID를 안정적으로 유지해 화면별로 군집이 달라지지 않게 한다.
- 복구 모드 검사와 0/1/100 트리거 검사, 경계 통과 검사를 웹/데스크톱 양쪽에 적용한다.
